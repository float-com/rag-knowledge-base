# ChatService 流式问答主链路（时序图）

对应代码：`backend/app/services/chat_service.py` → `stream_answer()`

## 图 1：`stream_answer` 十步执行时序

```mermaid
sequenceDiagram
    autonumber
    participant ROUTE as SSE 路由层
    participant SVC as ChatService
    participant WS as 请求级 session
    participant DB as PostgreSQL
    participant NODES as 工作流节点
    participant LLM as 大模型 qwen-plus
    participant FE as 前端

    Note over ROUTE,FE: 一次流式问答的全过程，左侧编号与代码里的步骤注释一一对应

    ROUTE->>SVC: stream_answer(conversation_id, question)
    activate SVC

    rect rgb(255, 245, 235)
    Note over SVC,DB: 步骤 1 会话校验，使用请求级 session
    SVC->>WS: get_conversation(conversation_id)
    WS->>DB: SELECT conversations WHERE id
    DB-->>WS: 会话行 或 空
    alt 会话不存在
        SVC--xROUTE: 抛 NotFoundError
        Note over ROUTE,FE: 此时流尚未开始<br/>HTTP 仍可正常返回 404
    end
    end

    rect rgb(240, 248, 255)
    Note over SVC,DB: 步骤 2 开独立 session，与请求生命周期解耦
    SVC->>DB: async with AsyncSessionLocal
    Note over SVC,DB: SSE 长连接期间不占用请求级连接<br/>避免并发时耗尽连接池
    end

    rect rgb(245, 255, 245)
    Note over SVC,NODES: 步骤 3 装历史与查询标准化，顺序不能颠倒
    SVC->>NODES: load_context(state, session)
    NODES->>DB: SELECT messages ORDER BY created_at DESC LIMIT window×2
    DB-->>NODES: 历史消息，已反转为正序
    NODES-->>SVC: 增量 chat_history

    SVC->>NODES: normalize_query(state)
    Note over NODES: 当前为透传，query 等于 question<br/>为后续指代消解预留扩展点
    NODES-->>SVC: 增量 query
    end

    rect rgb(255, 250, 235)
    Note over SVC,DB: 步骤 4 落库用户提问并单独 commit
    SVC->>DB: INSERT messages role=user
    SVC->>DB: COMMIT
    Note over SVC,DB: 先落提问再调大模型<br/>LLM 失败时用户问题不丢，便于前端重发

    SVC-->>FE: SSE message_start<br/>data user_message_id
    end

    rect rgb(250, 245, 255)
    Note over SVC,NODES: 步骤 5 检索与拒答熔断
    SVC->>NODES: retrieve(state, session)
    NODES->>LLM: aembed_query 生成查询向量
    LLM-->>NODES: 1024 维向量
    NODES->>DB: ORDER BY embedding <=> 向量 LIMIT top_k
    DB-->>NODES: Top-K 切片与距离
    Note over NODES: refused = 召回为空<br/>或 Top-1 相似度低于 0.6
    NODES-->>SVC: 增量 retrieved_chunks 与 refused

    SVC-->>FE: SSE citations<br/>data citations 含 ordinal 从 1 起
    end

    rect rgb(240, 255, 250)
    Note over SVC,LLM: 步骤 6 生成分支
    alt refused 为真 拒答熔断
        Note over SVC,LLM: 完全不调用大模型<br/>把 retrieve 预置的拒答文案作为唯一 token 下发
        SVC-->>FE: SSE token 仅 1 次
    else refused 为假 正常生成
        SVC->>NODES: stream_generate(state)
        activate NODES
        NODES->>LLM: astream 组装好的 messages
        loop 逐块返回
            LLM-->>NODES: 文本增量
            NODES-->>SVC: yield delta
            SVC-->>FE: SSE token 逐字
        end
        deactivate NODES
        Note over SVC: 编排层负责累积拼接并回写 state answer<br/>生成节点自身不写 state
    end
    end

    rect rgb(255, 240, 245)
    Note over SVC,DB: 步骤 7 落库助手回复与引用，单事务保证原子
    SVC->>DB: INSERT messages role=assistant 含 refused 元数据
    opt refused 为假
        SVC->>DB: INSERT answer_citations 批量，ordinal 从 1 起
        Note over SVC,DB: 拒答路径没有可溯源原文<br/>因此跳过引用写入
    end
    SVC->>DB: COMMIT 一次性提交消息与引用
    Note over SVC,DB: 两者要么一起成功要么一起回滚<br/>避免出现有回答但点不开引用的半成品

    SVC-->>FE: SSE message_end<br/>data message_id 与 refused
    end

    deactivate SVC

    Note over SVC,FE: 异常路径：流一旦开始，HTTP 状态码已固定为 200<br/>后续异常无法再改用 4xx 表达，必须转成 error 事件下发
```

## 图 3：客户端视角的事件流

同一时刻前端看到的东西：

```mermaid
sequenceDiagram
    participant FE as 前端
    participant API as POST /conversations/id/chat

    FE->>API: 建立 SSE 连接
    API-->>FE: event message_start<br/>可以开始渲染用户气泡
    API-->>FE: event citations<br/>侧边展示引用列表
    loop 逐字
        API-->>FE: event token
    end
    API-->>FE: event message_end<br/>用 message_id 替换本地临时消息
    Note over FE,API: 任何阶段出错则收到 event error，不再有 message_end
```

## 关键设计点速查

| 设计点 | 代码位置 | 为什么 |
| --- | --- | --- |
| 会话校验用请求级 session | `stream_answer` 开头 | 发生在流式开始之前，此时仍可返回 404 |
| 流式用独立 session | `async with AsyncSessionLocal()` | SSE 长连接不能占用请求级连接，否则耗尽连接池 |
| `load_context` 必须早于落库提问 | 步骤 3 先于步骤 4 | 否则本轮提问会被当成历史读回来 |
| 用户提问单独 commit | `_persist_user_message` | LLM 失败时问题不丢，便于前端重发 |
| `message_start` 在检索之前发 | 步骤 4 之后 | 前端尽早拿到 `user_message_id` 占位，参考资料的耗时（embedding 约 1 秒）不阻塞首屏 |
| 拒答时 `token` 只发 1 次 | 步骤 6 的 `if` 分支 | 完全不调 LLM，机制上不给幻觉机会 |
| 累积拼接由编排层做 | 步骤 6 的 `answer_parts` | `stream_generate` 是异步生成器，无法同时 yield 碎片又 return 完整 dict |
| 助手消息与引用同一事务 | `_persist_assistant_message` | 避免"有回答但点不开引用"的半成品数据 |
| 拒答不写引用 | 步骤 7 的 `opt` 分支 | 拒答没有可溯源的原文依据 |
| 异常转 `error` 事件 | `except` 分支 | 流已开始则 HTTP 状态码固定 200，抛给上层无法表达 |

## 实测事件序列（真实运行结果）

```
正常分支:  message_start -> citations -> token × 48 -> message_end
           回答 403 字，耗时 7.4 秒，落库 2 条消息 + 5 条引用

拒答分支:  message_start -> citations -> token × 1  -> message_end
           回答为固定拒答文案，未调用大模型，落库 2 条消息 + 0 条引用
```
