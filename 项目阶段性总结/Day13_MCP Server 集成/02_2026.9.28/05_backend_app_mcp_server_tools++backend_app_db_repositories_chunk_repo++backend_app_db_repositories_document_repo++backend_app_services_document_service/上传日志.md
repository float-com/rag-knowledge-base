三、★ `_viewer_tags`：全模块唯一的权限来源

```python
def _viewer_tags(user: User) -> list[str] | None:
    return None if is_admin(user) else compute_user_permission_tags(user)
```

· admin 传 None 而不是 ["*"]：服务层约定 None = 不做权限过滤；
  ["*"] 语义上也等于全可见，但它要多走一遍"数组重叠"的 SQL 运算 ——
  既然 admin 本来就不需要过滤，传 None 让 SQL 少一个条件更直接
· ★ 必须与 REST 侧同口径（网页侧路由也是 admin → None）：
  一旦 MCP 侧自己判一套可见范围，就会出现"网页看不到、Agent 却能看到"的双口径漏洞 ——
  第 1 章 §3.5 的头号风险
· ⚠️ 注意 permission_tags 有两个语义，别混：
    工具 2（上传）的入参 permission_tags = "我要给这份文档挂什么标签"（写）
    _viewer_tags(user)                      = "我能看到哪些标签"（读）

· 需要的三项全局聚合，项目里一个都没有（实测）：

    切片总数（按可见范围）    ❌ 只有 chunk_repo.get_stats(document_id)（单文档）
    最近一次 ready 时间       ❌ 没有
· 补的三处（3 个仓储方法 + 1 个 dataclass + 1 个 service 方法，★ 三个统计方法全部集中在 document_repo）：
    document_repo     + _permission_where（build_permission_filter 的一行转发别名）
                      + count(permission_tags=...)
                      + count_chunks(permission_tags=...)
                      + get_last_indexed_at(permission_tags=...)
    document_service  + KnowledgeBaseStats（@dataclass(frozen=True)）
                      + get_stats(permission_tags=...) → KnowledgeBaseStats
  ⚠️ chunk_repo 最终【无净改动】：曾加过 count_chunks 与 _permission_where，
     按教程把三项聚合集中到 document_repo 后已撤回（不留无人使用的私有函数）

· ★ _permission_where 为什么只是一行转发：
    教程第 7 节的统计 SQL 用的就是这个名字，本项目已有 build_permission_filter。
    保留这个私有别名可以让统计代码与教程逐行对应，但**口径仍只有一处定义**
    （标签重叠 OR 空标签即公开、通配短路）—— 它绝不是"第二份权限实现"。

· 四个关键取舍：
    · count 为什么不复用 list_paginated：后者会连带把当前页 ORM 实体全查出来，
      而概览只要一个数字 —— 为 count 去加载整页文档是纯浪费
      （套一层 int(...) 的理由同 UserRepository.count_all：func.count() 静态返回 int | None）
    · count_chunks 为什么必须 join documents 且带 status == "ready"：
      权限标签挂在父文档上（切片没有自己的标签），不 join 就拼不出权限条件；
      ready 守卫是"可被检索"的判据，与 vector_search / keyword_search 的第一条 WHERE 一致 ——
      少了它，正在解析甚至解析失败的切片也会被算进"知识库规模"，Agent 判断"值不值得检索"会失真
    · get_last_indexed_at 为什么取 updated_at 的 max，且只查 documents 表：
        updated_at  文档转入 ready 且 reindex 成功后刷新 → 正是"入库完成"的落点
        created_at  只反映上传时间，两者差着整条解析/切分/向量化流水线
        join ingestion_tasks 取 finished_at → 会引入"任务被清理后时间就丢了"的依赖
        用 max() 而不是 order_by + limit 1：少一次排序，语义更直白
        标量聚合要用 scalar_one_or_none()：没有行时 max() 返回 NULL，得到 None 而不是 0
      ⚠️ 这一条正是我第一版做错的地方（当时把它挂在 chunk_repo、走了 join），已按教程改回

· get_stats 为什么放 Service 而不是工具里：
  第 1 章定的纪律 —— MCP 工具层只做协议转换、不碰数据访问；
  三个 count/max 属于"业务口径"（哪些算可见、ready 才算可检索），
  放 Service 才能与网页侧将来可能的复用共享同一口径
· 返回 KnowledgeBaseStats（dataclass, frozen）而不是 dict：
  键名拼错在【调用处】就能被静态检查抓到，而 dict 只能等运行时 KeyError；
  且与既有 ChunkStats 同手法（frozen 快照）、与第 3 章 MCPStats 强类型契约对齐
· ⚠️ 一处刻意的命名偏离：教程把 chunk 计数也写在 document_repo 并叫 count，
  本项目落在 chunk_repo.count_chunks —— 因为 chunk_repo 已有 get_stats(document_id)
  （单文档切片统计，Day3 就在用），再放一个 count 会让"统计"在同一文件里指向两种粒度。
  **行为与权限口径与教程完全一致，只是落点不同**

六、★ 工具 4 的协议翻译：字符串 → UUID

· document_id 在 MCP 侧声明成 str 而不是 UUID，是有意的：
    声明成 UUID → 格式不合法会变成协议层的参数校验错误，模型看到的是一段 schema 报错；
    声明成 str + _parse_uuid 显式解析 → 能给出"document_id 不是合法的 UUID"这句可操作的话
· _parse_uuid 捕获 (TypeError, ValueError) 两个：
    uuid.UUID() 对类型不对（None / int）抛 TypeError，对格式不对抛 ValueError；
    只写 ValueError 的话，上游传了非字符串就会冒成工具内部错误
· ⚠️ 与教程的一处差异：教程把 from uuid import UUID 写在【函数体内】，
  本项目统一放模块顶部（文件头已有），我只就地使用、不再重复导入，
  并在 docstring 里写明了这一处差异与理由（函数内 import 会让依赖来源难追踪）

  用 PostgreSQL 方言编译）：
    permission=None / ['*']（通配即不过滤，两条等价）
      count                SELECT count(*) FROM documents
      get_last_indexed_at  SELECT max(documents.updated_at) FROM documents
                               WHERE documents.status = %s
      count_chunks         SELECT count(*) FROM document_chunks
                               JOIN documents ON ... WHERE documents.status = %s
    permission=['public']（普通用户：权限条件正确拼上）
      count                ... WHERE (permission_tags && %s::VARCHAR[])
                                OR permission_tags = %s::VARCHAR[]
      get_last_indexed_at  ... WHERE documents.status = %s AND ((permission_tags && ...) OR ...)
      count_chunks         ... WHERE documents.status = %s AND ((permission_tags && ...) OR ...)
    ⚠️ 两点：① count(['*']) 与 count(None) 编译结果完全相同、都没有 WHERE（正确，
    通配与 None 是同一条路径的两种入口）；② get_last_indexed_at 只查 documents 表、
    无 join —— 这是按教程第 7 节校正后的形状（我第一版挂在 chunk_repo 上走了 join，已改回）
