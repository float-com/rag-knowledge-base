五、★ 修复的 4 项 P0（按顺序）

· P0-1 数据库与 Redis 暴露到宿主机
    现状证据：docker ps 实测 0.0.0.0:5432->5432 与 0.0.0.0:6379->6379
    ★ 为什么不能直接改基础 compose：本地 api/worker 跑在宿主机、连的是 localhost:5432，
      撤掉端口映射本地立刻连不上库
    改法：新增 docker-compose.prod.yml（只 expose、不 ports；api/worker 进容器走服务名）
          + backend/Dockerfile（多阶段构建 + 非 root 运行）
          + backend/.dockerignore（排除 .venv / .env / 模型 / 测试产物）
    验证：docker compose config 渲染 → 5432/6379 无 published；连接串为 @postgres:5432

· P0-2 JWT_SECRET 缺配只告警不阻断
    改动：config.py 新增 environment（默认 development）与 is_production；
          warn_if_jwt_unconfigured 改为按环境区分：
            development → 告警放行（本地/教学不受影响，行为与第 12 期一致）
            production  → 空密钥 / 短于 32 字符 直接抛 ConfigurationError 拒绝启动
          并对默认管理员弱口令额外打 ERROR 告警
    验证：6 个场景（开发空/弱密钥放行、生产空/弱密钥拒绝、生产合规放行、PROD 别名识别）

· P0-3 默认管理员口令 admin
    改动：.env.example 的 DEFAULT_ADMIN_PASSWORD 改为 CHANGE_ME_BEFORE_FIRST_START
          + 新增 .env.prod.example（全占位符、可提交；.env.prod 仍被 .gitignore 忽略）
    说明：本项只在"库内无用户"时生效；库已建号时必须用 SQL 重置（检查单里有命令）
    ⚠️ "首登强制改密"（users 加 must_change_password 列）成本较高，列为上线后事项

· P0-4 ★ MCP 通道没有任何限流
    成因：MCP 是 app.mount("/mcp", ...) 挂进来的独立 ASGI 子应用，
          【不走 FastAPI 的依赖链】→ 第 12 期给 REST 挂的 enforce_rate_limit 对它完全无效
    而 ask_knowledge_base 烧 LLM、upload_document 烧 embedding 与 COS
    ★ 这是第 12 期"新加一条通路要重新打钩能力清单"那条约定的【第三次复现】：
      第一次是直传链路漏挂鉴权，第二次是限流漏挂直传，这次是 MCP 整条通道
    改法：新增 app/mcp_server/limits.py::enforce_tool_limit(user, scope=...)
          在 ask 与 upload 各调一次；三个只读工具【刻意不限】
          key = rag:rate_limit:mcp-<scope>:user:<id>
    两个设计要点（写进代码注释）：
      ① mcp- 前缀与 REST 额度隔离，否则 MCP 问一次、网页侧少一次额度，用户会莫名 429
      ② 按 scope 分桶，避免"传大文件把问答额度吃光"
    验证：阈值打桩为 3 → 前 3 次放行、第 4 次被限（文案正确）；
          key 命名正确；upload 分桶独立；只读工具不受影响

六、留档的 2 项 P1（处置方式：知道并接受）

· P1-1 每次 MCP 调用一次 307 重定向（POST /mcp → 307 → /mcp/）
    成因：内层子应用路径设为 "/"，Starlette 对 mount 根路径的规范形式是带尾斜杠
    影响：MCP 客户端都会自动跟随，功能不受影响
    真正风险：反向代理不跟随重定向 → 表现为"连不上"却查不到原因
    处置：写进检查单（确认反代配置 + 用真实客户端连一次，本次已实测 Inspector 通过）
    若要彻底消除需去掉 streamable_http_path="/" 并重算 mount 前缀，收益小，保留

· P1-2 依赖锁在 mcp 1.30.0 + fastmcp 2.14.7（旧世代）
    背景：为了教程的 from mcp.server.fastmcp import ... 可用而回落
    当前状态：两者仍在维护、不是 EOL，短期可接受
    升级是一次破坏性迁移（FastMCP → MCPServer、streamable_http_app → http_app 等）
    建议：等教程第 13 期讲完再【单独】升级，不要边写文档边升
          （否则代码与教程截图全面对不上，第 2 章已为对齐教程返工过一轮）
