## 坑一：缓存命中路径漏写 `state["answer"]` → 助手消息静默落库失败

### 症状（很有欺骗性）

```
第二次问语义相近的问题：
    前端 ✅ 完整收到 209 字的答案
    前端 ✅ 收到 5 条引用
    前端 ✅ 收到 cache_hit=true
        ↓
    刷新页面 / 查历史 → ❌ 这条回答【消失了】
```

后端日志里只有一句几乎看不出问题的：

```
[error 事件] {'code': 'chat_stream_failed', 'message': "'answer'"}
```

### 根因

```
常规路径：流式生成结束后有一步回写
    state["answer"] = "".join(answer_parts)
        ↓
缓存路径：我把缓存的答案 yield 给了前端，但【忘了写回 state】
        ↓
_persist_cached_assistant_message 里读 state["answer"]
        ↓
KeyError: 'answer'
        ↓
外层 except 捕获 → 回滚事务（助手消息 + 引用一起丢）
→ yield error 事件
```

**为什么这个 bug 特别隐蔽**：

| 掩盖因素 | 说明 |
| --- | --- |
| 答案已经发出去了 | `yield` 发生在落库**之前**，前端已经拿到完整回答 |
| 异常被兜住 | 流式响应的异常必须转成 error 事件（HTTP 码早已固定为 200），不会 500 |
| 用户无感 | 只有"刷新后这条消息不见了"这一个表现，且要刷新才发现 |

### 修法

```python
# _stream_cache_hit 里，紧随落库用户消息之后：
state["answer"] = cached.answer      # ★ 绝不能漏
```

并留了注释说明：**落库方法读的是 `state["answer"]`，这是与常规路径的同一个约定。**

### 可迁移的教训

```
"先把结果发给用户、再落库"这种顺序里，
任何"落库要用到的中间状态"都必须在发结果之前就位。

因为发出去之后，后续失败只能走"降级提示"这条路 ——
用户已经看到答案了，再告诉他"这条没存上"是很糟糕的体验，
所以设计上就会倾向于"静默兜住"，而静默兜住 = 问题被藏起来。
```

## 坑二：`return_fields` 漏了 `vector_distance` → 相似度阈值静默失效

### 症状

```
年假有多少天？     这个与"差旅费怎么报销"毫不相干的问题
        ↓
    却命中了差旅费的缓存 ❌
```

### 根因

```python
hits = await self._cache.acheck(
    vector=query_embedding,
    filter_expression=Tag(_SCOPE_FIELD) == scope,
    num_results=1,
    return_fields=["prompt", "response", "metadata"],   # ← 少了 vector_distance
)
...
distance = hit.get("vector_distance")     # → None
if distance is not None:                  # ← 于是整段判定被跳过
    ...相似度比较...
return CachedAnswer(...)                  # → 直接当成命中返回
```

**RedisVL 只返回你点名的字段。** 漏掉 `vector_distance` → 拿到 None →
`if distance is not None` 条件不成立 → **相似度阈值那一段代码根本没执行** →
任何被 Tag 过滤后召回的结果都被当成命中。

### 为什么它比一般 bug 危险

```
它是【静默】的：不报错、不告警、日志干干净净
它让【安全/质量参数】失效：SEMANTIC_CACHE_MIN_SIMILARITY 形同不存在
它的表现是"缓存命中率特别高" —— 看起来像好事
```

### 修法（两处一起改）

```python
# ① return_fields 补上
return_fields=["prompt", "response", "metadata", "vector_distance"],

# ② 拿不到距离时【保守判为未命中】，而不是跳过判定
if distance is None:
    logger.warning("semantic cache hit without vector_distance, treat as miss ...")
    return None
```

**② 比 ① 更重要**：它把"漏字段"从一个**静默失效**变成了**响亮地不命中 + 一条 warning 日志**。
即使将来有人手滑删了那个字段，也只是"缓存不生效"，而不是"任意命中"。

### 可迁移的教训

```
给"可选参数"写 `if x is not None:` 分段判定时，
必须想清楚【x 为 None 时应该走哪条路】。

    跳过判定  → 等于该参数不存在（危险）
    保守拒绝  → 等于"条件不满足"（安全）

凡是这个参数关系到【安全或质量】的，一律走"保守拒绝"。
```

## 坑三：缓存引用指向已删除的 chunk → 外键失败，回滚整条消息

> 这一处是**测试手法不当先触发**的（我用假 UUID 造引用），
> 但它暴露的风险是真的，已在代码里修掉。

### 风险场景

```
缓存条目最长存活 SEMANTIC_CACHE_TTL_SECONDS（默认 1 小时）
        ↓
这 1 小时内，管理员把那份文档删了
        ↓
缓存里的 citations 仍带着当时的 chunk_id / document_id —— 指向不存在的行
        ↓
缓存命中时按"原样搬运"插入 answer_citations
        ↓
ForeignKeyViolation → 整个事务回滚 → 助手消息一起丢
```

**关键细节**：两个外键虽然是 `ON DELETE SET NULL`（允许为空），
但**插入时 PostgreSQL 仍会校验 id 是否存在**：

```
answer_citations_chunk_id_fkey:    FOREIGN KEY (chunk_id)    REFERENCES document_chunks(id) ON DELETE SET NULL
answer_citations_document_id_fkey: FOREIGN KEY (document_id) REFERENCES documents(id)      ON DELETE SET NULL

"允许为空" ≠ "可以填一个不存在的 id"
```

### 修法

落库前批量校验一次存在性，不存在的置 `None`：

```python
# citation_repo 新增两个方法
async def existing_chunk_ids(self, chunk_ids) -> set[UUID]     # SELECT id WHERE id IN (...)
async def existing_document_ids(self, document_ids) -> set[UUID]
```

`chunk_id` / `document_id` 置 None 后**引用卡片依然能正常展示** ——
因为 `document_name` / `quote` / `page_no` 都是当年冗余下来的快照字段。
**这正是当初冗余快照的意义所在。**

代价：固定 2 次查询，与引用条数无关。

### 可迁移的教训

```
"快照数据"跨越了它的数据源的生命周期时，
必须在【写回源系统】前重新确认源还在 —— 或者只写快照、不写引用。

外键的 ON DELETE SET NULL 只保护"删除时不炸"，
不保护"插入一个早已被删的 id"。
```

## 附：相似度阈值必须实测定标（教程的 0.92 在本项目命中不了）

这不是 bug，但**不改就发现不了缓存有任何作用**。

### 实测数据（text-embedding-v3，中文问答，9 组样本）

| 关系 | 相似度区间 | 0.92 下是否命中 | 0.75 下是否命中 |
| --- | --- | --- | --- |
| 相近（换说法） | 0.7589 ~ 0.8819 | ❌ **全部不命中** | ✅ 命中 |
| 相关但**不同问点** | 0.8381 | ❌ 不命中 | ✅ 命中（可接受） |
| 无关 | 0.4154 ~ 0.5161 | ✅ 挡住 | ✅ 挡住 |

**可行区间是 (0.5161, 0.7589]**，取 **0.75**（落在偏严一侧）。

### 具体样本

```
差旅费怎么报销？  vs  出差费用如何申请报销呢     0.8809   相近
差旅费怎么报销？  vs  报销的流程是什么          0.7589   相近（更短）
差旅费怎么报销？  vs  差旅报销需要哪些材料       0.8381   相关但不同问点
员工请假流程是什么？ vs 我想请假，需要什么手续    0.8819   相近
员工请假流程是什么？ vs 请假怎么办              0.8769   相近
差旅费怎么报销？  vs  年假有多少天？            0.5161   无关
差旅费怎么报销？  vs  今天天气怎么样            0.4154   完全无关
```

### 结论与提醒

```
⚠️ 0.92 是"拍出来"的值，在这个模型 + 中文问答上：
     换说法（0.76~0.88）全都低于它 → 缓存永远不会命中
     而它"看起来"又是合理的（很像"严格"）

⚠️ 换 embedding 模型后【必须重新定标】——
     这个阈值只对 text-embedding-v3 有意义
```

> 📌 **定标方法**（本次用的就是这套）：准备 6~10 组样本 ——
> 几组"换说法"、几组"相关但不同问点"、几组"完全无关"，
> 算两两余弦相似度，看"相近的最低分"与"无关的最高分"之间的区间，取区间内的值。
> 脚本思路存在本项目的验证记录里，重新定标时照做即可。
